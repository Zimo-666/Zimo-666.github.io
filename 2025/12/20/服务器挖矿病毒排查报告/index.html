一、事件概述

事件基本信息‌

事件：两台麒麟服务器，受害时间为9月14日，受害IP为118.123.172.211，外联的矿池地址136.*.*.53，于 2025 年 12 月进行系统排查。

‌

事件表现‌

针对两台受感染服务器开展应急处置，现已查明木马文件路径与持久化手段。经样本分析确认，该病毒关联矿池为 136.244.89.53 与 randomx.xmrig.com。目前，两台终端的挖矿病毒及其残余项已清理完毕，系统恢复正常运行。

三、样本分析

样本概述

文件类型: ELF 64-bit LSB executable, ARM aarch64, version 1 (SYSV)

链接方式: Statically linked (静态链接)

架构: ARM64 (AArch64)

核心功能: 门罗币 (XMR) 挖矿工具，确认为 XMRig 的重命名版本。

静态分析发现

伪装与混淆

文件名伪装: 恶意程序被命名为 “https” “sh” 等，试图伪装成常见的网络协议名称，以在进程列表（如 ps 或 top 命令）中混淆视听。

无加壳: 样本未加壳，可以直接通过 IDA Pro 进行反汇编和字符串分析。

内置配置: 程序包含硬编码的 JSON 配置文件，即使在没有外部参数或配置文件的情况下也能独立运行。

配置文件加载机制

程序启动后（入口点 start @ 0x40319C -> main @ 0x402058），会按照以下优先级尝试加载配置：

外部文件: 尝试读取当前目录下的 config.json。

隐藏文件: 尝试读取当前目录下的 .xmrig.json。

用户配置: 尝试读取 $HOME/.config/xmrig.json。

内置默认配置: 如果上述文件均不存在，则加载内存地址 0x8303F0 处的硬编码 JSON 配置。

内置挖矿配置详解

通过分析内置的 JSON 字符串（地址 0x8303F0），提取出关键挖矿参数：

矿池地址：

主矿池: ssl-v.dns-aliyun.com:443

伪装: 域名伪装成阿里云 DNS 服务 (dns-aliyun.com)，实际指向攻击者的矿池代理或私有矿池。

备用矿池：136.244.89.53:80，即本次监测到的矿池地址

IP 归属: 该 IP 位于海外，通过 HTTP 端口 80 通信。

算法: 支持 RandomX, CryptoNight 等多种算法，程序会自动检测 CPU 指令集（如 AVX2, AES）以优化算力。

挖矿流程

初始化阶段

硬件检测: 程序启动时会检测 CPU 核心数、缓存大小（L2/L3 Cache）以及是否支持大页内存（Huge Pages），以最大化挖掘效率。

网络初始化: 使用 libuv 库初始化异步网络 I/O 线程池。

协议交互

连接:

函数 sub_458348 解析矿池 URL（stratum+tcp:// 或 stratum+ssl://）。

建立 TCP 连接，如果配置了 TLS，则进行 SSL 握手。

登录:

函数 sub_4440D0 构建 JSON-RPC 请求。

发送 {“method”: “login”, “params”: {…}} 包，包含钱包地址和客户端标识。

任务分发:

接收矿池下发的 mining.notify 通知，获取任务 Blob。

哈希计算:

调用 RandomX 或 CryptoNight 算法函数（如 cryptonight_v8 等）对数据进行哈希运算。

结果提交:

当计算出满足难度的 Nonce 时，调用 sub_46C2A8。

发送 {“method”: “mining.submit”, …} 将结果回传给矿池。

传播与威胁评估

传播能力

结论: 该样本本身不具备蠕虫传播能力。

证据:

搜索 “scan”, “exploit” , “ssh” 等关键词，未发现相关攻击代码。

虽然存在 “SSH Client” 字符串，但经分析为未引用的死代码（可能是静态链接库残留）。

程序逻辑仅限于：加载配置 -> 连接矿池 -> 挖矿 -> 提交结果。

威胁来源

该程序通常作为攻击链条中的次生载荷（Payload），由蠕虫病毒、自动化攻击脚本或后门程序在成功渗透后从远程服务器下载并静默加载执行。

四、处置建议

1. 隔离受害主机

切断外网： 在防火墙上封禁受害主机的外网访问（尤其是非业务端口的出站流量）。

阻断通信： 针对已知的矿池域名或 IP（通过 netstat 或 ss 命令获取），在 hosts 文件中指向 127.0.0.1。

2. 终止恶意进程

识别高占用： 使用 top 或 htop 按 CPU 使用率排序。

定位文件： 使用 ls -l /proc/[PID]/exe 查看进程对应的文件路径。

强制杀掉： 执行 kill -9 [PID]。注意：某些病毒有守护进程，需同时杀掉或先暂停（kill -STOP）。

3. 清理持久化项

计划任务： 彻底检查 /var/spool/cron/、/etc/crontab 及 /etc/cron.d/ 下的所有文件。

启动服务： 检查 /etc/systemd/system/ 和 /etc/init.d/，移除异常的 .service 文件。

SSH 秘钥： 重点检查 ~/.ssh/authorized_keys，删除非本人授权的公钥，防止黑客通过后门二次进入。

4. 彻底删除病毒文件

清理残留： 根据步骤2获取的路径删除二进制文件，并清理 /tmp/、/var/tmp/、/dev/shm/ 等常驻目录。

检查隐藏文件： 注意以 . 开头的隐藏文件或具有特殊属性（如 chattr +i）的文件。

5. 溯源与加固

排查入口： 重点“两高一弱”，即高危端口、高危漏洞、弱口令。

修改凭据： 强制修改所有系统用户密码，尤其是具备 sudo 权限的用户。

强化防护： 启用 iptables 或 firewalld 仅开放必要端口，安装并运行 Rootkit 检测工具（如 chkrootkit）。
